AI session summary

Recommended KoboldCpp launch profile · Gemma 4 12B Q4_K_M · 8 GB VRAM

These are KoboldCpp launcher settings, not values Trance can change after the server starts. Use a Gemma 4-capable KoboldCpp build (1.111.1 or newer). For an NVIDIA GPU select CUDA; GPU Layers -1 enables AutoFit so KoboldCpp offloads only what fits and keeps a VRAM safety margin. Gemma 4 is template-sensitive: use Jinja / chat-completions mode.

--model "PATH_TO_GEMMA_4_12B_Q4_K_M.gguf" --usecuda --gpulayers -1 --contextsize 4096 --quantkv q8_0 --batchsize 128 --ubatchsize 128 --jinja --useswa --chat-template-kwargs '{"enable_thinking":false}'

For CPU-only inference, launch KoboldCpp with --usecpu instead of the CUDA and GPU-layer flags. CPU mode is slower, and Trance connects to either backend through the same KoboldCpp address.

For Gemma 4, explicitly enable SWA with --useswa; it substantially reduces KV-cache VRAM. Keep FlashAttention enabled (required for full KV quantization and on by default in current KoboldCpp builds). Start with batch / physical batch 128; if you still hit out-of-memory, reduce both to 64 and let AutoFit offload fewer layers to the GPU. A 12B Q4_K_M model plus cache and compute buffers is not expected to fit wholly in 8 GB, so CPU layer offload and adequate system RAM are expected (32 GB system RAM is more comfortable than 16 GB). If you use image-aware AI comments, load the matching Gemma 4 vision projector; if VRAM is still tight, add --mmprojcpu to keep that projector in system RAM, with slower image analysis. Text chat and session summaries do not need the projector. Do not disable FlashAttention as a VRAM workaround.

Suggested starting point: 4K context, Q8 KV cache, batch sizes 128 (64 if needed), one active request, Jinja enabled, SWA enabled, and Gemma 4 thinking disabled so short Trance requests do not spend their output budget on reasoning. This app-side 4K context limit is only a prompt-safety cap: set the same 4096 context in KoboldCpp.
